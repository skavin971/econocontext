Omnigent in EconoContext

Omnigent runs the agent. EconoContext watches it through two plugs: the model URL and a policy. Everything else (the agent loop, its tools, sessions, the transcript, a web UI) comes from Omnigent for free.

Yes, we ran Omnigent

Omnigent is running on this machine at http://127.0.0.1:6767. The bench started a real session for the SWE-bench task, the agent fixed the bug, and the official SWE-bench grader marked it resolved.

Observe mode means EconoContext saw every model call and every tool result, computed and logged what it would do (83 decisions), and changed nothing. The agent ran exactly as it would without us. That is the safe first step. The next step is the same task in both arms (baseline and econo), then five tasks.

What Omnigent is

Omnigent is not a chat app. It is a server that runs agent sessions. The chat screen is one client of that server; our bench is another client that uses the same API with no screen at all. It has three parts:

PartWhat it doesDo we need it?
RunnerRuns the harness loop (think, call a tool, read the result, repeat) and executes the agent's tools on this machineneeded This is the agent
Server + APICreates sessions, stores every step, evaluates policies, tracks costneeded The bench starts tasks here; our policy plugs in here
Web UIA viewer: the list of sessions and each one's full transcriptoptional For people reading what the agent did

The harness that actually solves the task is the OpenAI Agents SDK (Omnigent's openai-agents harness), thinking with Gemini 3.6 Flash. None of that code is in our repo; it is installed with Omnigent and chosen in bench/agent.yaml.

Does Omnigent add latency?

Model calls go from the runner straight to our gateway on localhost and then to Gemini. The Omnigent server is not on that path. Measured on this machine, median of 40 calls against a local fake model, with a realistic mid-run request (30 messages, 68 KB):

WhatTimeAdded
Model call, straight to the model0.7 ms·
Through the gateway, baseline arm (forward and measure)2.2 ms+1.5 ms
Through the gateway, econo arm (also runs plan_prompt)4.9 ms+4.2 ms
Policy, per tool call0.4 ms+0.4 ms
Policy, per file-read result1.2 ms+1.2 ms
Policy, after an edit (runs git status, tiny repo)15.7 ms+15.7 ms

A short real Gemini call took 770 to 1,240 ms in the same session, so the gateway adds well under 1% per call. git status grows with the repository, so edits on a large repo will cost more than 15.7 ms. Starting a session's runner takes a few seconds, once per task.

Omnigent's cost figure is too high for our setup

Omnigent says our SWE-bench run cost $0.2586. That figure matches, to the last digit, a formula that charges every input token at the full price and leaves out reasoning tokens:

338,454 input tokens × $0.75/M   = $0.253841   (no cache discount)
  1,261 output tokens × $3.75/M  = $0.004729   (reasoning left out)
                                   $0.258569

Our gateway measured what Vertex actually reported for the same run: 90,039 fresh input tokens, 248,415 cached tokens (billed at a tenth of the price), and 3,082 output tokens including reasoning. The ledger prices that at $0.0977. We are not measuring wrong. Two things drop information on the way from Vertex to Omnigent:

  • The cache discount is lost to a field name. Omnigent reads cached tokens from usage.prompt_tokens_details, but the Agents SDK stores them as input_tokens_details. So Omnigent always sees 0 cached tokens.
  • Reasoning is left out. Vertex reports reasoning tokens outside completion_tokens, and the SDK copies only completion_tokens.

That is why EconoContext measures cost at its own gateway, from what the provider itself returned. The final check is the Google Cloud billing console.

What Omnigent does not give us

  • Policies never see the prompt, only a summary of each model call, and no per-call token counts. Both come from our gateway.
  • A policy cannot skip a tool. Answering a repeated read from the store is only logged.
  • Sub-agents do not work on our Gemini setup yet: Omnigent 0.15.0 sends them to an API Vertex does not serve.
  • Omnigent is alpha, so we pin 0.15.0 and keep the plug code small. Details: docs/omnigent-findings.md.

The UI, and what more runs add

Each new run adds one session to this list, with its full transcript. The UI shows what the agent did. It does not show what EconoContext decided or what each call really cost: that lives in our Agent DB and bench/report.py. Once we run both arms, you can open the two sessions side by side in the UI and compare them in the report.

See it yourself

.venv/bin/omnigent server status                 # is Omnigent running?
open http://127.0.0.1:6767                       # the UI: sessions and transcripts
.venv/bin/python bench/report.py --label q6b     # EconoContext's view of the same run

The UI opens on a new session. Pick "Fix pastebin lexer parameter to text" in the sidebar to see the SWE-bench run.
